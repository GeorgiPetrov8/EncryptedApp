## Сървър

1. Замени `src/db.js`. Новите таблици се създават сами при старт.
2. Добави `src/mailer.js` и `src/routes/recoveryRoutes.js`.
3. В `src/validate.js` добави `'edit'` към разрешените contentType:
   ```js
   'text', 'image', 'video', 'file', 'notePad', 'receipt', 'profile', 'invite', 'call', 'edit',
   ```
4. В `server.js`, при другите `router.*`:
   ```js
   const recovery = require('./src/routes/recoveryRoutes');
   router.get('/account/email', recovery.getEmailRoute(store));
   router.post('/account/email', recovery.setEmailRoute(store, limiters));
   router.post('/account/email/verify', recovery.verifyEmailRoute(store, limiters));
   router.post('/account/email/remove', recovery.removeEmailRoute(store));
   router.post('/backup', recovery.uploadBackupRoute(store, limiters));
   router.post('/backup/delete', recovery.deleteBackupRoute(store));
   router.post('/recovery/start', recovery.startRecoveryRoute(store, limiters));
   router.post('/recovery/verify', recovery.verifyRecoveryRoute(store, limiters));
   router.get('/recovery/backup', recovery.downloadBackupRoute(store, limiters));
   router.post('/recovery/rebind', recovery.rebindRoute(store, limiters));
   ```
   Ако routerът ти не изпраща `X-Recovery-Ticket` хедъра до handler-а (той
   го чете от `req.headers`), кажи ми.
5. **Имейли.** Без настройка кодовете се отпечатват в конзолата на сървъра,
   което стига за тест. За реални имейли задай:
   ```
   RESEND_API_KEY=re_xxx
   MAIL_FROM="HyperChat <noreply@твоят-домейн>"
   ```
6. Тест: `node test/recovery.test.js` → `15 recovery tests passed`.

## Как да тестваш възстановяването

1. На телефон А: Settings → Account Recovery → добави имейл → въведи кода
   (взимаш го от конзолата на сървъра).
2. Export backup file → парола → Save to Files. Направи и „Back up to server“.
3. Изтрий приложението на А (или вземи друг симулатор).
4. Login екран → Restore account → Backup file → избери файла → паролата.
   Всичко се връща, а контактите могат да ти пишат веднага.
5. Повтори с Email → username → кода → паролата.


# REAL EMAIL
За реални имейли са нужни три неща: акаунт в Resend, собствен домейн и две променливи на сървъра. Сървърният код е готов. mailer.js вече праща през Resend, щом намери ключ, а иначе печата кода в конзолата.

Вариант 1: бърз тест без домейн (5 минути)
Регистрирай се на resend.com. Не иска карта.
API Keys → Create API Key, с права Sending access. Копирай ключа веднага, защото после не се показва повече.
В папката на сървъра създай .env (npm start го зарежда автоматично):
RESEND_API_KEY=re_xxxxxxxxxxxx
MAIL_FROM=HyperChat <onboarding@resend.dev>

Рестартирай сървъра.

Ограничение: от onboarding@resend.dev писмата стигат само до имейла, с който си се регистрирал в Resend. До всеки друг адрес Resend връща 403 „You can only send testing emails to your own email address“. Става за тест на собствения ти акаунт в приложението, но не и за реални потребители.

Вариант 2: реално, до всеки адрес

Трябва ти домейн (около 10 €/година от Cloudflare, Namecheap и т.н.).

В Resend: Domains → Add Domain. Въведи поддомейн, например mail.твоят-домейн.com, а не главния домейн. Resend препоръчва това, за да не се смесва репутацията на тези писма с обикновената ти поща. За регион избери EU (Ireland), защото е най-близо до България.

Resend показва DNS записи. Добави ги при доставчика на домейна, като копираш стойностите, без да ги пишеш на ръка:

Тип	Име	За каквоMX	send…	връщане на отказани писма
TXT	send…	SPF
TXT или CNAME	…._domainkey	DKIM подпис
TXT	_dmarc	DMARC, по избор, но силно препоръчан

При Cloudflare: изключи проксито (оранжевото облаче да е сиво) за тези записи, иначе проверката не минава.

Натисни Verify. Обикновено отнема до 15 минути, но понякога до 72 часа.

Смени .env:

RESEND_API_KEY=re_xxxxxxxxxxxx
MAIL_FROM=HyperChat <noreply@mail.твоят-домейн.com>


Ако пускаш сървъра с Docker, добави двете променливи в docker-compose.yml под environment:.

Рестартирай сървъра.

Безплатният план позволява 100 имейла на ден и 3 000 на месец. Това стига спокойно за кодове за потвърждение.

Как да провериш
В приложението: Settings → Account Recovery → въведи имейл → Send verification code.
В Resend → Emails трябва да видиш писмото със статус Delivered.
Ако не пристигне, погледни конзолата на сървъра. Приложението винаги казва „Code sent“, нарочно, за да не издава информация, така че грешката се вижда само в сървъра.

Сега mailer.js логва само HTTP кода. За да виждаш и причината от Resend, смени този ред:

JavaScript
if (!res.ok) console.error(`[mail] provider rejected message: HTTP ${res.status}`);
Show more lines

с:

JavaScript
if (!res.ok) console.error(`[mail] provider rejected message: HTTP ${res.status} ${await res.text()}`);
Show more lines
